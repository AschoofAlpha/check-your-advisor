*[English](README.md)*

你要选硕导或博导。手里只有一个名字、一个实验室自己写的主页，没有任何办法核实。
这个工具去 PubMed 把这个人的发表记录读出来，还给你一堆**带分母的事实**。

**它不告诉你这个导师好不好。**那是你的判断。它做的是把传闻换成数字，
并且每个数字后面都跟着"从多少人/多少篇里算出来的"。

```bash
python scripts/run.py harvest --author "Wang Wei" --orcid 0000-0002-1825-0097 \
    --years-back 10 --output-dir ./record --no-download
python scripts/run.py cite    --output-dir ./record
python scripts/run.py profile --pi-name "Wang Wei" --output-dir ./record
```

三条命令，一份 HTML 报告。不需要装任何东西，纯标准库。

## 它回答什么

- 这个组这些年出现过谁
- 一作名额落在谁头上，集中还是分散
- 新人等多久才拿到第一个一作
- 人一般待几年
- 这个老板自己在署名里站哪儿 —— 末位、通讯，还是也做具体活
- 年产出多少，是不是反复投同几本刊
- 引用数和 h-index，连同它们的覆盖率
- 一个 0–100 的综合分，每个分项的原始输入都印出来

以及两件需要你提供表格才能算的：这些期刊在**你查的那一版**里是什么档次，
还有 **有多少人在这里毕业却一篇被收录的论文都没有** —— 那正是上面所有数字都看不见的一群人。

## 它拒绝什么，以及为什么这个区分重要

"不告诉你导师好不好"背后其实是四件性质完全不同的事，报告里是分开写的：

| | 例子 | 为什么 |
|---|---|---|
| **算，且落盘** | 引用数、h-index、综合分、名次、星级、字母等级、拟合斜率、花名册排名、引用数在外部参照池里的百分位 | 是测量，带分母印出来 |
| **拒绝** | 在**你加载的那几份语料**里的位置、综合分的百分位、年度百分比变化 | 是决定，见下 |
| **等你给表** | 影响因子、JCR 分区、中科院分区、毕业名单 | 授权数据库或有反爬，工具只给 schema 不给爬虫 |
| **永远看不见** | 组里氛围、老板人品、没读完就走的人 | 任何数据库里都没有 |

**「在你加载的那几份语料里的位置」不是不给，是算不出来** —— 那几份语料是你自己选的，
加一份删一份，同一个人的位置就变了。这条至今有效。

**但「引用数的百分位」第四轮给了**，因为它问的是另一回事：`cite --percentile` 会问
OpenAlex，这篇论文的引用数在**所有同领域同年发表的论文**里排第几。那个参照池
不随你加载什么而变，别人跑同一个查询会得到同一个池子。

这里有个必须说清的坑：百分位用的是「引用数**严格少于**本篇的论文占比」。
实测某领域某年 3808 篇里有 1399 篇零引用 —— 如果用「小于等于」，
每一篇零引用论文都会因为站在并列块顶端而拿到 **65 百分位**，
把「没有人引用过」印成「中位偏上」。用严格小于，零引用就是 0.0，那是真话。
另一种读法连同并列篇数一起并列印出，不替你选。

**定位不到的论文绝不会被当成低百分位。** 七种情况各有各的名字和一句说明
（没拿到引用数、没有标识符、topic 查不到、OpenAlex 没记 topic、没有年份、
参照分布取不到、参照池太小），报告里逐条印出来。「没算出来」和「排得低」是两件事。

## 语料决定一切

每个数字都是在 `harvest` 留下的那批论文上算的。如果混进了同名的另一个人，
花名册、等待时长、人员流动全都是错的 —— **而且错得在页面上完全看不出来**。

**至少给 `harvest` 一个唯一标识。**按强度排：

| 参数 | 强度 |
|---|---|
| `--orcid 0000-0002-...` | 最强，一个顶其余全部 |
| `--email-domain your-university.edu.cn` | 通讯作者邮箱域名，可重复给 |
| `--affiliation-keyword "..."` | 最弱 —— 同一个大学系统里的同名同事挡不住 |
| `--resolve-openalex` / `--openalex-author-id A...` | OpenAlex 自己的作者聚类。记为 OpenAlex 的断言，不记为你的 |

`--resolve-openalex` 会把 OpenAlex 里所有用这个名字发表的作者逐条印出来，
带作者 ID、ORCID、机构履历和作品数。**只有一位候选时才采用；两位及以上时全部列出、
一个都不选** —— 按作品数挑等于用产量代替身份，而且事后报告里看不出做过这个选择。
认出是哪一位后加 `--openalex-author-id` 重跑即可。

完全没配身份证据时，报告**照常生成**，但第 0、1、19 节顶部各挂一个提示框，
写明是哪一条、观测到的数是多少、怎么修；第 14 节如实记下"这一条以前是拒绝出报告的"；
进程退出码仍然是 1。以前这里是直接拒绝，代价是十六节已经算出来的事实一起作废 ——
其中就包括第 19 节，而那正是唯一能让读者看出语料里到底是不是一个人的一节。
这样的语料在 `compare` 页上照样不给名次：行在、分在，位置不给。

真正危险的情况一个提示都不会触发：证据太弱会产出一份完整、看起来很正常、
实际描述好几个人的报告。实测一次：某位中国外科医生，只用省名而非完整机构名做关键词，
抓回 28 篇，横跨胃肠外科、分析化学、结构生物学、土壤微生物和机器学习 —— 综合分 78.2。

**第 19 节就是查这个的。**它把 PI 本人从作者里去掉（他按定义在每篇上），
问剩下的论文还能不能靠共同作者连成一片。一个人的产出是被他合作的人维系的；
两个同名的人没有理由共享任何第三者。它**不设阈值** —— 实测数据不支持任何阈值，
所以它只把簇和各簇的期刊印出来，判断交给你。通常一眼就能看出来。

## 想要第二个来源

```bash
python scripts/run.py harvest --author "Wang Wei" \
    --openalex-author-id A5023888391 --openalex-works --output-dir ./record
```

把该作者 ID 名下的 OpenAlex 作品拉回来并入 PubMed 语料，去重顺序是
DOI → PMID → 归一化标题+年份。两边都有的那篇以 PubMed 的记录为准 ——
它带机构字符串和通讯作者邮箱，下游每一道身份校验都读这两个字段，OpenAlex 没有。
每条记录都标明来自哪个源、被哪些源确认过，第 1 节把两个分母都印出来：
合并语料和 PubMed 语料是两个数，不合成一个。两个 API 都不需要密钥；
`--email` 会作为 OpenAlex 的 `mailto` 发出，那是限速通道，不是认证。

## 三张要你手工填的表

影响因子、JCR 分区、中科院分区都是有授权的商业产品，没有免费可再分发的来源；
学位论文库有反爬；学生评价散在论坛和评价站上，更不允许自动采集。
所以这里给的是 schema、待查清单和 join，不给爬虫。
（确实会联网取的只有两样：引用数，以及下一节的期刊风险信号 ——
都走条款允许的免密钥公开接口，都单独成带日期的文件，绝不写回你手填的表。）

```bash
python scripts/run.py journal-worklist --output-dir ./record
```

它生成的 CSV **只包含这份语料实际用到的期刊** —— 通常二十来本，不是全球两万本 ——
ISSN 和篇数已经填好，指标列留空。你从任何有权限的来源填完，然后：

```bash
python scripts/run.py profile --output-dir ./record \
    --journal-table ./record/journal_worklist_*.csv \
    --thesis-roster ./record/theses.csv \
    --evaluation-table ./record/evaluations.csv
```

期刊表有两列是**必填**：`版本来源`（官方版/新锐版/民间版/JCR）和 `数据获取日期`。
少了这两列，过两年那个分区数字就无法追溯。同一本刊查到两个版本就写两行，
两行都会印出来、不替你选，不一致的字段会单独列出。

> 实测提醒：LetPub 检索结果列表页默认显示民间版分区，要官方版得点进详情页；
> 科研通 ablesci.com 把官方版和新锐版分开标注，可以交叉验证；
> Clarivate MJL 免费但只有 SCIE/SSCI 收录状态，没有影响因子也没有分区。

毕业名单是三张表里最重要的那张。从学位论文库导出该导师名下的题录，
它能算出 PubMed 结构上不可能给的数字：**有多少毕业生一篇被收录的论文都没有。**
记得加一列姓名拼音，否则中文名单和英文署名根本对不上。
另外，入学后没读完就走的人在任何库里都没有 —— 这张表只是把缺口缩小，没有补上。

学生评价那张表完全靠你自己收集，没有对应的待查清单命令：
语料里有期刊名，所以 `journal-worklist` 能吐清单；语料里没有任何东西
指向「人们在哪儿谈论这位导师」，所以那一步只能是人干的。
必填列：`导师姓名`、`评价来源`、`数据获取日期`，外加 `评价内容` 与
`维度评分` 至少有一列；缺列在加载时就报错并点名缺哪一列。
第 20 节印出：归到本人名下几条、来自几个来源、时间跨度多长，
然后按文件顺序逐条列出，每条都带来源和获取日期。
**不做情感分析，不出均值或评级，也不进综合分** ——
这是少数几个愿意动手写点东西的人留下的说法，任何在其上算出的数字
量的都是「谁去发了帖」。原样列出、标注出处、注明日期，判断留给你。

## 第四张表：中文期刊题录

这是三张手填表之外的第四张，**而且它和那三张不是一回事**：那三张各喂报告的一节，
这张**改变语料本身**，报告里每个数字都会跟着变。

这正是它存在的理由。只查 PubMed 时**中文核心期刊完全看不见** ——
一位导师 PubMed 上 12 篇、中文核心 40 篇，那么「年产出」「一作名额分布」「人员流动」
全都是在四分之一的语料上算出来的，**而且页面上看不出来**。

```bash
python scripts/run.py profile --output-dir ./record     --chinese-records ./record/cnki.csv
```

必填七列：`篇名`、`作者`、**`作者拼音`**、`期刊`、`发表年份`、`数据来源`、`数据获取日期`。
缺哪一列在加载时就报错并点名。

**`作者拼音` 是这张表能不能用的分水岭。** 中文署名和罗马化的导师名跨字符集，
没有拼音列，导师在自己的署名里定位不到，这条记录就只能贡献「年产出」一个数。
定位不到的行**照样产出记录、不丢弃**，但不占任何署名位次，并且逐行报出原因。

编码按 `utf-8-sig` → `gb18030` 顺序试（顺序本身是安全措施：gb18030 几乎能解任何字节序列，
放前面会把 UTF-8 文件静默解成乱码还报成功）。两个都失败时给一句人话，不是裸的
UnicodeDecodeError。

**去重只有一级：归一化标题 + 年份。** 中文题录通常既没有 DOI 也没有 PMID，
所以做不到 PubMed/OpenAlex 合并那样的 DOI → PMID → 标题 三级去重。两个方向都会错：
同年同题的两篇不同论文会被并成一篇；同一篇论文 PubMed 收英文题名、知网收中文题名，
两种文字永远对不上，会算成两篇。所以跨源命中一律叫**「疑似重复」**并逐对列出，
**三个分母分别印出，不合成一个**。

## 半年后再看一次：`diff`

```bash
python scripts/run.py diff ./record-2026-03 ./record-2026-09
```

第一个目录是旧的，第二个是新的。出：新增几篇、谁第一次出现、一作名额落在谁头上。

**先读窗口那一段再读任何计数。** 如果两次检索的年份范围不一样，
「新增 7 篇」很可能只是这次多查了两年 —— 那不是新增，是口径变了。
所以每个「只在一侧」的计数都会再切一刀：多少篇落在两次都查过的年份内（这才是新增）、
多少篇落在只有一边查过的年份里（这是口径变了）、多少篇没有年份。
两份语料的检索窗口没被记下来时，它说**「比不了」**，而不是拿语料自身跨度凑一个答案。

**它只报「在哪一份语料里」，不说为什么。** 一篇论文在旧的里、不在新的里，
可能是撤稿、可能是检索式不同、可能是身份证据不同、可能是书目库当天的应答不同 ——
四种可能并列印出、不排序、不挑选。工具分不出来，也不猜。

## 公开风险信号 —— 只报事实，不下结论

关于一本刊，确实有三样东西是能免费查到的，一条命令就够：

```bash
python scripts/run.py journal-risk --output-dir ./record
```

DOAJ 收录状态、Crossref 元数据完整度、OpenAlex 刊记录，覆盖语料里每一本带 ISSN
的刊。三个免密钥公开 JSON 接口，各一次 GET，单独成文件，每条记录自带采集时间，
不写回语料、也不写进你手填的那张表。`profile` 自动接上最新一份，
第 18 节把每条陈述连同「哪个接口说的」和「哪天读的」一起印出来。

**这里不把任何一本刊称为掠夺性期刊。** 「掠夺性」是对出版方行为的指控，
这三个接口都没有做这个指控，本工具也不做。信号命中多少条都不会被折算成
等级、评分、字母或颜色，也不进综合分。你拿到的是
`未被 DOAJ 收录`、`Crossref 元数据缺失 3 项（共查 10 项）` 这样的句子，
带来源、带日期，怎么读是你的事。

其中两条几乎每次都被误读，所以报告里紧跟着写反话：
**未被 DOAJ 收录不是问题** —— DOAJ 只收主动申请的开放获取期刊，
Journal of Hepatology 不在里面，以后也不会在，医学领域大部分订阅刊同理。
**Crossref 某项元数据为 0 也不是问题** —— 它量的是出版方存了什么，
Journal of Hepatology 实测就是 10 项里 3 项为 0。

三个来源每次都查，谁也不算数。它们经常互相矛盾，矛盾就并列印出、各带日期。
OpenAlex 的 Scopus 字段对大量真实期刊返回 `null`，那是第三种取值，
绝不会被印成「未被 Scopus 收录」。

**中科院国际期刊预警名单不抓，也不会抓。** 它一年一版，以登录后网页和 PDF 发布，
没有任何机读端点，所以继续留在上面那张表手填的 `是否预警` / `预警等级` 列里。
那一栏空着意味着没人查过，本节任何信号都不会替它填上。

## 安装

当命令行工具用：

```bash
pip install check-your-advisor
check-your-advisor harvest --author "Wang Wei" --orcid 0000-0002-1825-0097
```

当 Claude Code 技能用 —— clone 到技能加载器会看的位置，让 `SKILL.md` 和代码待在一起：

```bash
git clone https://github.com/AschoofAlpha/check-your-advisor.git \
    ~/.claude/skills/check-your-advisor
```

也可以 clone 下来直接跑 `scripts/run.py`，它是唯一入口，完全不用装。

pip 包**不声明任何依赖**，这不是漏写：装完之后的干净虚拟环境里只有这个包、pip 和
setuptools，再无其他。两个可选 extras 都有经过测试的降级路径 ——
`pip install "check-your-advisor[pdf]"` 启用 PyMuPDF 的 PDF 隔离，
`[xlsx]` 启用 openpyxl 导出，`[all]` 两个都要。

## 可选依赖

三个都有经过测试的降级路径，都不是必需的。

- **PyMuPDF**（AGPL-3.0，所以刻意不做 MIT 项目的硬依赖）让 PDF 身份校验能把
  下错的文件隔离出去。没有它时每个下载仍然会检查 `%PDF-` 魔数。
- **openpyxl** 启用 `.xlsx` 导出。没有它就写成带时间戳的 CSV。
- **本机已装的任一 HTML→PDF 转换器** —— wkhtmltopdf、Chrome / Chromium / Edge、
  weasyprint 或 LibreOffice —— 让 `profile --pdf` 在 HTML 报告旁边多写一份 PDF。
  这几个都不会被 import，也不下载任何东西：工具只是调用一个已经装好的程序。
  一个都没有时 `--pdf` 会逐条打印怎么装，HTML 输出一个字节都不变 ——
  这正是重点：HTML 才是交付物，PDF 只是它的一份副本。
  `--pdf-converter` 指定用哪个；`--pdf-converter-path` 指定装了但不在 PATH 上的
  可执行文件全路径，Windows 上 Chrome 和 LibreOffice 通常都是这种情况。

## 测试

```bash
python tests/run_all.py
python tests/run_all.py --block-third-party
```

35 个文件 4905 条断言（2026-09-17 用上面第一条命令实测）。上面第一条命令每次跑都会重测这两个数，对不上就红，所以这是一个数而不是一句承诺。第二条命令会装一个
import hook，在每个测试进程里屏蔽
`requests`、`urllib3`、`pandas`、`numpy`、`matplotlib`、`fitz`、`openpyxl`。
这是"不需要装东西"这句话唯一的保证，而不是只是嘴上说说：
恰好三条断言在没有它们时行为不同，而那三条都是需要真实 PDF 文件的用例。

## 已知问题

- 报告是英文，命令行日志是中文。这不是谁能辩护的设计，是它长成这样的，统一是待办。
- ~~`cite` 没有自己的缓存。~~ **已解决**：`cite` 和 `journal-risk` 现在各自按
  「哪个接口 + 问的什么」缓存应答，和 PDF 缓存共用一个 SQLite 文件、两张互不干扰的表。
  缓存**每次成功抓取都写入，只在你加了 `--max-age-days N` 时才读取** ——
  所以默认那一趟仍然逐个源全问，只是把缓存焐热了，省下的是下一趟。
  命中时记录上带的是**当初真实采集那天**，不是本次运行的日期。
- 期刊名匹配对 ISSN 抓取功能之前建的语料只能退回 token 启发式。重抓一次可以拿到精确 join。
